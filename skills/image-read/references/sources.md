# 输入来源与证据适配

来源是识别手段，UI 解析模型保持一致。只读取本轮实际提供且可访问的内容，不强制某一种来源。

## 两阶段读取

1. 概览：读取足够的可见内容或节点结构，结合内置布局规则建立区域骨架。已有前序布局分析且对应同一来源、范围和状态时复用；先核对是否仍适用。
2. 细读：以骨架区域为读取单元，按请求深度补充控件组成、样式与几何。每项结果记录所属布局节点和来源定位。

概览阶段无须先枚举所有文字、色值、图标和叶子节点。后续证据若与骨架冲突，回到结构分析修正后再继续。
这一区分是分析依赖，不要求工具必须提供两个独立接口，也不要求重复获取已经返回的数据。

## 图片 / 截图

先观察整体或目标区域，确定骨架；随后按骨架区域查看局部、识别控件并选用测量工具。
局部裁切记录其所属区域与原图位置，测量结果回填该区域；不把裁切后的左上角直接当作原图或父容器原点。
一般结构和样式特征可直接描述；精确几何或采色才调用 Python 等测量手段。
读取真实尺寸、缩放、裁切与清晰度信息（可得时）；不默认无损、1:1 设计比例或固定 DPR。
无法确定的字体、热区、原始色值、响应式机制、不可见状态，标推断或未知。
独立资源的 alpha 分析与整页截图内嵌图标分析分开。

## Figma 链接 / 节点

仅在用户提供或指定该来源且有相应能力时使用；不把 Figma 设为必需依赖。
先按当前环境要求加载相应工具的 skill，再进行允许的读取。这里不硬编码某个连接器或工具调用方式。
先在实际可访问范围内读取足够的结构、布局或预览信息，整理语义骨架并建立“布局区域 → 源节点”映射。
再按布局区域细读相关子树中的相对几何、文字、填充、描边、效果、组件/实例及状态等所需属性，不无目的遍历范围外节点。
这些属性有则记录，无则未知；不能声称工具一定返回所有数据。
有渲染预览时结合预览校验可见结果，整理图层树为 UI 语义树；辅助 Group、隐藏层、组件名都不能单独决定控件角色。
组件的 variants 若读取到，可描述为设计提供的状态，不自动认定为运行时行为。
无需先导出 PNG 再量已有节点数值；节点读取不足时可按需使用已有预览或截图补充。
不能访问时如实说明；没有图片或节点内容时，不基于链接名称编造布局。

## 混合参考

为各来源编号，说明用途和用户指定的优先级。
将各来源中的区域或节点映射到同一语义骨架，再补充相应局部属性；未能对应的对象保留待定位，不强行挂到邻近区域。
同一属性冲突时并列记录：如截图为当前运行状态、节点为某版设计值，不能无依据判定谁更新。
坐标、单位、缩放和状态分别对齐后再推导；无法对齐时保留两份结果。
外部资料只解释模式与规范，不替代目标来源里的尺寸、文案和状态。

## 证据标签

- 源属性：直接读取设计/结构数据，注明节点或来源。
- 像素实测：实际读取图像像素或测定边界，注明输入和方法。
- 计算推导：列出公式及输入字段的依据。
- 视觉推断：依据可见外观推断角色、规律或近似值，说明关键不确定性。
- 未知：当前来源无法支持，不强填。
