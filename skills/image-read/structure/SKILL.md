# Structure

布局模式查 [../references/layouts.md](../references/layouts.md)，组合场景查 [../references/scenarios.md](../references/scenarios.md)。

## 三种关系

1. 语义从属：页面 → 工具栏 → 搜索框；列表 → 行 → 行操作。
2. 布局关系：横向/纵向排列、网格、对齐、分配空间、跨列、间距、锚定和覆盖。
3. 视觉组成：控件的底面、文字、图标、描边、指示器等；按深度展开。

保留三者差异：弹窗可覆盖页面但不是页面卡片的子布局；浮动菜单可归属触发器但位于独立浮层。
bbox 包含只能辅助判断，不能单独证明父子关系；遮罩、重叠和装饰层尤其如此。
Figma 图层树是结构证据，需要整理为语义树，不把每个 Group 当成 UI 分区。

## 分析顺序

- 找到本轮根对象，区分宿主窗体标题栏、应用页头、内容区及浮层；仅列实际存在的部分。
- 按真实分组识别区域、列槽、卡组和卡片。每个范围内列槽都要检查子块，不要求左右结构对称。
- 描述方向、主次区域、对齐、间距、边距、滚动边界、裁剪与层级。
- 按深度展开语义控件，使用 [../references/controls.md](../references/controls.md) 的组成规则。
- 重复列表、卡片、网格优先提取模板，再记录数量、可见差异和例外。

## 骨架与控件

进入局部细读前，形成范围内的布局树，为区域赋予稳定短名或路径，并记录可用的源节点标识或图像区域位置。
后续控件、视觉子层和测量项都引用这个归属。重复项可挂在同一模板下，并保留实例差异与定位。
已有前序骨架时先核对来源、范围和状态后复用；不因换用图片识别或节点工具而另建一套互不关联的树。
发现新分组或从属判断错误时，更新受影响的树节点、来源映射及已有结果；仍未知的关系明确标注。

容器可以同时具有填色、描边、圆角和布局规则，不限定为只表达包含。
按钮作为一个语义控件保留；样式分析需要时再展开底面、图标、标签。
列表保留视口、重复行、行内字段与行操作的关系；不要将每个文字节点都升成独立区域。
单独有尺寸、出现在清单里，不意味着是独立卡片或列。

截图可支持“左右排列、顶对齐、右侧留白”等观察；auto-layout、固定/填充/自适应等机制仅在有源属性或其它证据时作为确定事实。
响应式换列、吸顶、拖动分栏等行为：仅在多视口、可操作页面或源属性有证据时确认，否则注明推断或未知。

## 输出与检查

输出语义骨架树和必要布局说明，节点短名应能与控件、样式和几何记录对应。
检查点名对象无遗漏、各列实际子块有覆盖、重复模板例外已记录、覆盖关系未误写成普通包含关系。
骨架深度无需控件叶子；局部任务无需补齐范围外区域；无法辨认的节点保留未知，不能为凑完整而编造。
