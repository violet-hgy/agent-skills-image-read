# UIRead（安装标识 image-read）

## 定位与边界

以 UI 语义解析为主线：区域 → 容器骨架 → 控件组成 → 样式与可见状态。
图片、截图、Figma 节点是并列的输入来源；任何一种都不要求另一种存在。
Python、像素采样、节点读取、外部检索是按需手段，不是整个解析流程的前置依赖。

本包只交付解析报告，不修改 UI 工程或设计稿，不自行调度写码 skill。
宿主可以在报告交付后继续用户已授权的实现任务；报告结束不意味着必须再问一次许可。

## 工作流

1. 读取 [classify/SKILL.md](classify/SKILL.md)：分别确定来源、范围、深度与 UI 场景。
2. 按任务查阅内置规则，禁止无差别加载全部参考：
   - 布局骨架：[references/layouts.md](references/layouts.md)。
   - 控件组成、样式与可见状态：[references/controls.md](references/controls.md)。
   - 页面、弹窗、列表等组合场景：[references/scenarios.md](references/scenarios.md)。
3. 读取 [structure/SKILL.md](structure/SKILL.md)：先建立范围内布局骨架、父子关系与区域标识，作为后续识别的索引。
4. 沿布局树逐区域识别控件，再按需要读取 [visual/SKILL.md](visual/SKILL.md) 与 [geometry/SKILL.md](geometry/SKILL.md)，补充样式和几何。
   需要额外证据或精度时，才读 [gates/SKILL.md](gates/SKILL.md) 选择工具。
   来源适配见 [references/sources.md](references/sources.md)。
5. 遇到内置规则未覆盖的布局或控件，读取 [references/external-research.md](references/external-research.md)，针对缺口检索。
6. 按 [output/SKILL.md](output/SKILL.md) 交付与本轮范围和深度对应的报告。

## 先布局，后细化

先对实际来源作概览读取，获得足以判断区域和布局关系的信息；这一步允许查看图片、Figma 预览或必要的节点结构。
形成布局骨架后，后续图片局部识别、Figma 节点细读和 Python 测量都以该骨架为依据，按区域与父子关系展开。
每个控件、样式和测量结果归属到已有区域，保留来源定位，不能先堆积零散属性再凭清单顺序拼布局。
工具一次返回完整节点数据时可以复用，不为形式上的分步重复调用；分析顺序仍是先整理布局，再解释局部。

布局骨架是可修正的工作模型，不要求先由用户确认。后续证据发现结构错误时，先修正相关布局节点与归属，再继续细化，不能强套旧骨架。
只处理局部或单控件时，建立目标及必要父级的最小骨架即可；只看骨架时，到此交付，不继续展开细节。
骨架无法确定的区域保留未知；其内部从属关系暂不作为确定事实，其他已确定区域可以继续。

## 内置优先

内置规则覆盖客户端与前端常见布局、控件及组合界面。先按结构特征匹配，允许多个模式组合。
现有模式足以解释时，不因平台、产品名称或皮肤不同而检索；无法解释的新布局机制或控件模式才构成缺口。
用户明确要求检索、核验最新规范或阅读指定外部资料时，遵循用户要求。

内置模式用于组织观察，不能覆盖输入证据。不要为了套模板而补出图中没有的分区、控件或状态。
单张截图不能证明响应式行为、实际组件库、布局引擎、不可见交互或隐藏内容。

## 证据与完成原则

关键属性按字段注明依据：源属性、像素实测、计算推导、视觉推断、未知。
同一控件允许尺寸来自节点、外观来自截图；保留来源和冲突，不静默混合数值。
精确数值必须有来源或测量依据。观察到左右排列，可以描述为横向排列，不能直接宣称使用某框架的布局 API。

- 范围优先：整页参考不意味着整页展开；骨架解析不要求控件细节。
- 维度优先：只取文案不强制测字号、颜色；只取颜色不强制量全部几何。
- 语义优先：保留按钮、列表等控件身份，视觉子层按深度展开；容器也具有样式和布局属性。
- 能力局部降级：工具不可用只影响依赖它的字段。继续交付可支持的分析，明确未完成的精确测量。
- 不默认截图为无损原图，不把模糊、遮挡或压缩造成的未知编成精确参数。
- 输出必须对用户可见；不得把内部分析当成交付，不宣称报告已完成 UI 还原。
