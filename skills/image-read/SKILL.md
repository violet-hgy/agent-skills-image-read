# ImageRead

## 定位

```text
ImageRead（本包）  →  结构化像素报告（可视参数表）  →  结束

写图（可选）      →  项目 specializations/<lang>/  +  bindings
                   由宿主 SOP 读仓库推断 GUI 栈后决定是否进入
```

**只读图、只出数。** 不实现 UI，不改 Figma，不落资源清单。

## 与「一次对齐」的关系（本包不是写码 skill）

**一次对齐**是**任务级合同**（整链：参数 → 落码 → 同轮自校），由**宿主 SOP**执行写码与收尾。  
**不是** ImageRead 的功能，本包**不写码**、不宣称【一次对齐完成】。

本包只提供合同中的 **识图前置交付**：对用户可见的完整参数报告。没有这份报告，宿主不得写码（否则不算一次对齐）。

```text
任务合同「一次对齐」（宿主 SOP）
  ├─ 识图前置（本包主责）→【像素参数表】… →【ImageRead完成，等待宿主消费报告；本阶段不写代码】
  └─ 写图 + 自校（宿主 / 特化）→【写码许可】→ 落码 →【一次对齐完成】
```

用户点了一次对齐 / 按图实现：仍**先**完成本包报告；禁止因「要对齐/要写码」在本包内改 UI。

## 本包结束后

ImageRead **不负责推断项目 GUI 语言**（那是宿主 SOP 的事）。本包结束后：

- **只识图 / 评审** → 报告即交付。  
- **要写码** → 宿主读仓库（如 `qml/`、`*.tsx`）推断栈；匹配特化或 LLM 读参数表自行写码。

本仓库 QML 特化：`.cursor/portable-skills/specializations/qml/`（QML 栈且要写码时由 `design-to-qml` 调度）。

## 自动触发（Agent 自动挂载）

**位图** = 栅格图：PNG、JPEG/JPG、WebP、GIF、BMP、TIFF，以及截图/聊天附图（格式不论）。不含 SVG 矢量源、不含 Figma 节点树。

**位图默认 = 无损原图。** 禁止以“有损/信息不足/要二次精调”为由少测或要求开发口头二次确认。

**命中任一且像素来自位图时，必须先 Read 并执行本 skill 全流程，再写 UI 代码或报尺寸：**

- 用户附图、控件切图、整页截图（PNG/JPEG/WebP 等）
- 意图：按图还原、像素对齐、量尺寸、设计评审、**实现图内 UI**、对齐稿面（且源是图）
- 对话要求【识图场景】、一次对齐（仍先出报告，写码不在本包）或对 **位图** 出像素表

**硬门控：** 有位图要写 UI / 报几何 → **禁止**跳过本 skill 直接写码或「大约」填数。  
**报告必须对用户可见：** 完整参数表写在对用户的回复正文里，禁止只在思考中“做过测量”、禁止先改文件再补报告。

### 明确无效的借口（出现即流程失败）

下列理由**一律不能**用来跳过或延后【像素参数表】：

- 「尽快可见效果 / 先把 UI 和按钮做出来再补参数」  
- 「先搭骨架 / 先能跑 / 先给个近似界面」  
- 「参数以后再对齐 / 报告可省略」  
- 「用户急着看效果所以先写码」  
- 「大致看着像就行，不必输出参数表」

命中任一条 → 立刻输出【流程回退】，停止改 UI 文件，先补完整 ImageRead 报告。

**不触发：**

- **纯 Figma**（仅链接/`node-id`，无用户位图）：用 Figma MCP 节点 px，**不要**对本 skill / 导出 PNG 再量
- 无图、仅改已知文案/色/逻辑、纯协议或后端任务

**与 project-bindings 无关：** 有无 `project-bindings.md` **不影响**本 skill；bindings 只在写码阶段需要。

**【识图场景】码（classify 产出）：** `dialog-sheet`、`delegate-row`、`control-full`、`page-layout`、`showcase-align`、`overlay-badge`、`visual-tweak`、`measure-only`、`text-extract`。细则见 `./classify/SKILL.md`。

## 嵌套结构

```text
image-read/
├── SKILL.md
├── classify/ gates/ geometry/ structure/ visual/ output/
```

## 调度顺序（强制 · 仅识图）

1. `./gates/SKILL.md` — **环境放行**。Python=测量运行时；测图用任一准确可用后端（不强制 cv2）。无可用后端 →【ImageRead环境未就绪】并结束。禁止估算填表、禁止写 UI。
2. `./classify/SKILL.md` → 【识图场景】+【测量范围】+【元素清单】（先定范围；`layout-only` 不拆叶子）
3. `./structure/SKILL.md` → 再 `./geometry/SKILL.md` 按范围内清单实测（控件级才含叶子）
4. `./visual/SKILL.md`
5. `./output/SKILL.md` → 完整报告（完备性按范围+颗粒度）

**gates 未 OK 时本包职责已终止**（修环境后再从头执行）。gates OK 后才出完整报告。

## 两阶段协议（强制）

### Phase 1：只产出识图报告

当本 skill 被触发时：先跑 **gates**（确保 Python + 至少一种测图后端可用）。环境 FAIL 时首次输出只能是【ImageRead环境未就绪】，**不是**完整参数表，也**不是** UI。

环境 OK 后，**本轮首次实质性输出必须是 ImageRead 报告**，且只允许：

- 执行 `classify → structure → geometry → visual → output`（先【测量范围】；`layout-only` 只测容器骨架，控件级再展开叶子）
- 输出【识图场景】【测量范围】【元素清单】与完整报告区块
- 【测量完备性】按范围+颗粒度达标；猜测仅限不可测单字段
- 标注【需确认】仅真缺信息（禁止无损原图借口）

**Phase 1 禁止：**

- 任何 UI 实现代码（含 `Write`/`StrReplace`/创建 QML 等改文件动作）  
- 任何“先给你一个可见界面/近似还原/尽快可见效果”的方案或借口  
- 任何绕过参数表的布局建议  
- 把 SKILL 总说明、口头摘要、自然语言概述当作“已完成报告”  
- 只在内部思考里列尺寸、不对用户输出【像素参数表】等区块  

**Phase 1 对用户可见的最低交付（缺一不可）：**

本轮在**写任何 UI 代码之前**，用户消息中必须已经出现完整报告区块（见下「报告完成门控」），并以结束语收束：

```text
【ImageRead完成，等待宿主消费报告；本阶段不写代码】
```

没有这条结束语 = Phase 1 未闭环 = **禁止**进入写码。

### Phase 2：本包结束；写码不在本包

ImageRead **至此结束**。若宿主还要写 UI：必须先消费本包报告（【写码许可】），再由宿主 SOP / 特化落码与自校。  
写码、自校、【一次对齐完成】**不是本 skill 的步骤**，见宿主 SOP（如 design-to-qml）。

禁止：把一次对齐理解成「先做完 UI 再精调」，从而跳过本包报告。

只有本包完整报告（含清单完备、猜测占比门控通过）后，宿主才能写码。

写码开始前，宿主须在回复中写出（原样可检）：

```text
【写码许可】已见 ImageRead 完整报告（含【像素参数表】【测量完备性】）
```

未见该许可句、或许可句之前对话中找不到【像素参数表】 → **禁止**改 UI 文件。

## 硬规则

- 禁止未读图写参数表；禁止「大约」当实测  
- 猜测必须【暂时猜测数值占用】；**可测几何禁止猜测**  
- 有图必须先有【识图场景】+【测量范围】+【元素清单】  
- `layout-only`：测完容器外框/分栏/gap 即可，禁止拆内部控件  
- 控件级：范围内含叶子；未测完 / 只测容器外框 → 报告未完成  
- 禁止因整页截图就展开范围外叶子；未测范围外叶子不算失败  
- 阴影只记不当描边  
- 设计 px + 注明 scale；用户口头 px 优先  
- **默认无损原图**；禁止据此要求开发二次确认  
- **禁止**本包识图流水线内写码  
- Python 未就绪，或无任何可用测图后端：**禁止**后续 SOP 与整表估算  
- 当前后端失败：先自动修，仍失败则换其它可用后端实测；禁止目测估算  
- **不强制 cv2**；【元数据】写明实际使用的测图后端  

## 报告完成门控（强制 · 写 UI 前）

如果你的目标包含“实现图内 UI / 写代码 / 报几何 / 修改布局”：

- **gates FAIL**：只输出【ImageRead环境未就绪】并停止  
- **gates OK**：须先有完整报告，且含【测量范围】【元素清单】【测量完备性】且门控通过  

报告必须至少包含下列区块标题（原样）：

- `【识图场景】`
- `【测量范围】`
- `【元素清单】`
- `【像素参数表】`
- `【视觉参数表】`
- `【结构专表】` 或 `不适用`
- `【测量完备性】`
- `【需确认】`
- `【差异 / 不确定】`
- `【暂时猜测数值占用】` 或 `无`

未包含任一项或完备性门控失败：

```text
【ImageRead未完成】缺少：<区块名列表或完备性原因>
请先补齐清单实测，再继续写 UI。
```

若在完整报告前已经输出过实现代码/方案，或曾以“尽快可见效果”为由跳过参数表，视为**流程失败**：

```text
【流程回退】已进入实现但未先完成 ImageRead 报告（或借口跳过参数表）。
停止一切 UI 改动；先补完整报告（含【像素参数表】），再继续写码。
```

禁止把“本 SKILL.md 的总说明”当作完成报告。  
禁止“边写码边补测 / 写完再补报告”。
