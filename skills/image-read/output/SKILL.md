# Output

报告对用户可见、自解释，可供后续实现消费；不夹带 UI 实现代码。
格式随任务规模调整，不要求逐字复用全部标题或把不适用内容填满。

## 通用内容

1. 解析任务：来源、目标范围、深度、场景。
2. 布局骨架：区域/容器/控件树及排列、对齐、覆盖与滚动关系；指定提取可只给必要定位。
3. 控件与样式：按本轮深度列类型、角色、从属、组成、样式和可见状态。重复项用模板 + 差异。
4. 证据与不确定：关键属性的依据、来源冲突、工具限制、不可见或无法确认的字段。
5. 覆盖结果：哪些请求已完成、哪些仍未完成及原因。

## 按需附加

- 指定提取：提取目标、属性维度与对应内容，不强制附带未请求的全部 UI 属性。
- 精确测量：坐标参照、单位、缩放依据、几何/色值记录及测量方法。
- Figma 来源：实际读取的文件/节点标识与相关属性；不要求图片来源提供这些字段。
- 外部检索：内置规则缺口、检索结论、来源链接、适用边界。外部规则不作为目标 UI 的实测参数。
- 资源分析：资源外框、墨迹框、透明边距及显示关系；仅列能够支持的字段。

## 示例：骨架与控件解析

设置主体 → 分类导航 + 详情区；详情区 → 标题说明 + 设置分组 + 操作区。
设置分组 → 带标签的输入框 + 带说明的开关行。
布局关系：两栏横向排列；详情分组纵向排列，标签与控件按行组织（视觉推断）。
控件组成：开关行 = 标签 + 辅助说明 + 右侧开关；仅报告可见状态。
不确定：只有一个视口，未确认侧栏宽度策略、窄屏重排和点击行为。
覆盖结果：骨架与控件组成已覆盖；未请求逐像素测量。

## 完成检查

- 点名目标及请求属性已覆盖，范围外未无故展开。
- 树与清单一致，控件语义保留，容器样式未因不是叶子而遗漏。
- 局部识别、节点属性和测量结果可对应到前序布局树；无法定位的项已标注，后续结构修正已同步到相关记录。
- 布局关系与实现机制区分；可见状态与未验证行为区分。
- 精确值有证据，推断和未知已标明；不同来源的数值未混用。
- 工具失败影响的请求项明确列为未完成，不阻断其余有依据的内容。
- 实际外部检索时给出支持结论的直接来源链接。
- 本轮临时测量文件已清理。

不再强制旧固定结束语；用覆盖结果说明报告是否完成。报告不能宣称实现、交互或像素还原已通过验证。
